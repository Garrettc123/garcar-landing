# Garcar Enterprise — Eight-Division Operating System

Status: planning/specification package on a working branch. This does not claim eight production businesses.

## Corporate model
Garcar Enterprise is the parent company. Each division owns a distinct catalog, buyer, sales pipeline, delivery standard, and operating metrics. Shared services provide identity, evidence, finance reconciliation, authorization, security, and reporting.

## Truth labels
- Existing artifact: located in a repository or supplied project context; existence does not prove it works in production.
- Created in this branch: authored and committed planning/specification content.
- Planned: proposed offer, feature, workflow, price, or target not yet built or validated.
- Verified: directly checked through an identified test, record, or system response.
- Not verified: deployment, revenue, integration, security, or operational state has not been demonstrated.

## Baseline
The repository already contains the digital-products catalog, four sales-page drafts, email campaign drafts, and delivery architecture. The catalog labels the collection launch_preview_not_for_sale; four products are marked manuscript_created and eight are planned. Four Garcar business-product catalog assets are listed separately. The live website deployment, payment fulfillment, and email delivery are not verified here.

The parent README describes a service checkout flow and service offer keys. That is not proof of successful payment or a working digital-product entitlement flow. The existing delivery architecture explicitly says not to reuse service checkout links.

## Release rule
A plan, catalog, page, or code file does not make a division production-ready. Each division must pass customer validation, delivery testing, security review, finance reconciliation, and owner release approval. No paid activation, live payment, outbound email, or production deployment is authorized by this package.
