# Garcar Enterprise — Shared Sales Operating System

## Purpose
Use one evidence-based sales process across all divisions while keeping catalogs, buyers, qualification, delivery, and revenue reporting separate.

## Unified pipeline
| Stage | Entry condition | Exit evidence |
|---|---|---|
| Target identified | Fits documented segment hypothesis | Source and fit reason |
| Permission checked | Lawful basis or inbound initiation | Permission source and scope |
| Discovery requested | Prospect agrees to discuss | Accepted meeting request |
| Discovery completed | Problem/current process discussed | Notes, buyer role, pain, impact |
| Qualified | Problem, urgency, authority, feasibility, budget path understood | Qualification record |
| Demonstration | Relevant workflow shown safely | Demo scope and feedback |
| Proposal | Scope, price, exclusions, timeline, criteria shared with permission | Proposal artifact/version |
| Contract | Terms accepted | Signed agreement |
| Paid | Processor confirms payment | Transaction and reconciliation |
| Delivery | Agreed work completed | Acceptance evidence |
| Retention | Ongoing value confirmed | Renewal/repeat record |

A lead, conversation, verbal interest, proposal, invoice, payment link, test charge, or unpaid order is not collected revenue.

## Minimum CRM fields
division_id; offer_id; account/audience; contact role (avoid unnecessary personal data); source; permission status/evidence; problem statement; current process; quantified impact with source/confidence; qualification status; next step/due date; proposal version; contract status; processor payment reference; delivery status; outcome; last verified timestamp.

## Zero-cost validation
Start with inbound interest, referrals, public business information, and voluntary interviews. Do not buy lists, scrape private contact details, or mass-message. For each division, define one segment, one costly problem, one offer, and one proof artifact. Target five qualified conversations before expanding. Use synthetic data unless a customer authorizes a limited sample. Record negative feedback.

## Offer/proposal standard
State customer problem, target user, deliverables, exclusions, prerequisites, implementation, support, proposed price, acceptance criteria, risks, data handling, cancellation/refund terms.

## Messaging gate
Drafts may exist, but sending is disabled. Before any future send require explicit owner approval, lawful basis/consent evidence, accurate sender identity, required postal address, functional unsubscribe, suppression handling, reviewed copy, and test approval. This package sends nothing.

## Revenue reconciliation
Interest, proposal, invoice, payment link, and test payment are not customer revenue. Processor-confirmed live payment is gross collection subject to refunds/fees. Reconciled bank payout is cash received in bank. Report gross payments, refunds, fees, disputes, net processor balance, and bank payouts separately.
